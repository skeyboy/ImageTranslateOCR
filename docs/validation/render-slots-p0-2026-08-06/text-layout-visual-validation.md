# OCR 与译文纯文字页面回填验证

本页不使用原截图作为背景。左侧仅按真机 OCR 坐标绘制识别文字、区域框和语义组；右侧仅按服务返回的 `renderSlots` 绘制译文。外框尺寸分别严格对应新闻页 `387 x 892` 和聊天页 `1080 x 2400`。

颜色用于区分语义角色：蓝色为正文、棕色为标题、灰色为元数据、紫色为控件、绿色为标识符。每个译文组右上角的 `FULL/COMPACT/OVERFLOW` 是简易文本回流结果。

## 新闻页

![新闻页 OCR 与译文文字布局](./news-text-layout-comparison.svg)

人工核验重点：

- 首段十行从图片右侧的窄通道逐步扩展到图片下方全宽通道，右图应显示三个阶梯状槽，而不是覆盖成一个大矩形。
- `加拿大政府...` 译文应按三个槽连续阅读；若只出现在第一个槽，说明游标推进仍有问题。
- 左侧图片占用区在纯文字图中表现为空白；右侧译文不能进入该空白区。
- 标题、作者、Tweet/WhatsApp 控件必须保持独立，不应与正文合成大块。

结论：三个槽和正文阅读顺序与原页结构一致，绕图关系可以直观看出。使用单一 union bounds 会明显侵入左侧空白，因此 `renderSlots` 是必要数据，而不是可选布局提示。

## 聊天页

![聊天页 OCR 与译文文字布局](./chat-text-layout-comparison.svg)

人工核验重点：

- 17 行英文正文应形成一个连续大气泡组，电话号码、时间、域名和发送者仍是独立结构项。
- 右图中文应只占用 `[153,807,905,1769]` 的原气泡矩形，不向上下聊天记录扩张。
- 大气泡译文为 `FULL`；若出现 17 个独立中文框，说明服务失败后发生了分片降级。

结论：聊天页使用单矩形槽是合理的，因为 OCR 行宽一致且没有内嵌图片。与新闻页对比可以说明：组级翻译相同，但几何形状必须由 OCR 成员占用关系决定，不能把所有正文统一处理成一个矩形。

## 当前可直观看出的后续问题

1. 纯文字图能发现分组、阅读顺序、越界和错误扩张，但不能替代原图上的背景擦除、颜色、字体和对比度验证。
2. 网页与 Android 字体测量存在差异；本图用于结构核验，最终是否容纳仍以 Android `ShapeAwareTextLayout` 的真机结果为准。
3. 当前槽是轴对齐阶梯形，旋转文字、圆形环绕和透视文本仍需多边形或基线模型。

生成命令：

```bash
python3 scripts/render_semantic_layout_svg.py \
  --report docs/validation/render-slots-p0-2026-08-06/news-report-final.json \
  --output docs/validation/render-slots-p0-2026-08-06/news-text-layout-comparison.svg \
  --title 新闻页
```
