# Admin 服务端语义计划字号还原验证

日期：2026-08-07  
验证记录：<http://192.168.0.63:8090/admin/requests/34a94829-36f0-432c-a8d2-07d30b1f70e8>

## 问题

“服务端语义计划”原实现没有使用 OCR region 的真实行高，而是以槽位显示高度除以固定 `18px` 反推行数，再把字号限制在 `6px..11px`。在 1440×3200 页面按桌面面板缩放后，正文组被错误计算成大量虚拟行，最终四个计划槽全部使用 `6px`。状态标签同时占用槽内顶部 10px，进一步降低了首行还原度。

## 修复

- 按 `memberRegionIds` 查找原始 OCR 行框，使用成员行高中位数作为该语义组的源行高；
- 按服务端计划画布与原始 viewport 的宽度比例缩放字号，与“OCR 与语义组”面板采用相同的 `0.72` 字高系数；
- 保留 `sourceText` 的原始换行，多槽时按槽高分配完整 OCR 行；
- 仅在真实文字溢出时，从首选字号向 `68%` 下限做二分压缩；
- 状态标签移到组边界上方，不再占用 renderSlot 的文字高度。

## 实际结果

修改前，四个计划槽字号均为 `6px`。

修改后：

| 计划槽 | 字号 | 对应结构 |
| --- | ---: | --- |
| 第一正文组 | 18.711px | 7 行 |
| 第二正文组 | 17.8605px | 7 行 |
| 合并组首槽 | 18.9945px | 1 行 |
| 合并组正文槽 | 18.9945px | 8 行 |

同页 OCR 行字号范围为 `15.0255px..22.113px`，计划面板已经回到相同视觉尺度。画布无横向溢出，长标签位于组边界上方。

## 结论

该问题只影响 Admin 人工还原视图，不影响服务端 V3 响应和 Android 真实回贴。优化后服务端语义计划使用请求中已有的 OCR 几何进行字体还原，不再依赖固定字号或文章类型假设，可以更直接地对照“原始 OCR → 服务端合并组 → 译文 renderSlots”。
