# 确定性译文渲染 50 视口验证

> 执行日期：2026-07-29
>
> 设备：Xiaomi `23113RKC6C`，Android 16
>
> 配置：普通悬浮窗 `alpha=0.72`、局部背景、`STANDARD` 背景、并行渲染
>
> 基线：[实时屏幕翻译产品场景与验收基线](../../live-screen-translation-product-acceptance-baseline.md)

## 1. 结论

本轮第一优先级“确定性渲染验证”已完成。把 OCR 框和译文作为固定输入，直接送入生产译文贴片渲染链路后，50/50 个视口通过全部机器门：区域覆盖率 100%、裁剪 0、最低字号比例 0.684、最低对比度 6.41:1、系统/浏览器栏及非文字保护区保持率 100%，渲染 P50/P90 为 44/61ms。

因此可以确认：在 OCR 框准确、翻译完整且语义正确的上限条件下，当前渲染器能稳定完成结构化覆盖。现有漏译和持续中英混排主要受上游 OCR/翻译输入影响，不是渲染器随机漏绘造成的。

但 A7 完整体验只能判定为 **PARTIAL / 部分通过**。人工复核 Light、Dark、横屏、非文字混排和 2.5 倍译文长度样本后，未发现重叠、越界或 Chrome 污染，但普通 `alpha=0.72` 的局部灰色矩形仍有明显贴片感；暗色页面尤为厚重，局部区域还能看到轻微原文字形纹理。提高 OCR/翻译准确率可以解决缺失和混排，不能自动解决该材料问题。

生产决策不变：普通模式继续使用局部背景并默认关闭主题色/高斯；不恢复全页主题色，也不把全页高斯下放到普通悬浮窗。下一视觉候选应在相同确定性输入上 A/B 验证更贴近文字轮廓、边缘羽化的局部材料，同时保持页面结构、空间锚点和非文字内容。

## 2. 目标：最终要证明或交付什么

把 OCR 与翻译的不确定性从渲染器验收中隔离，回答两个问题：

1. 当输入框和译文完全可信时，生产渲染链路是否仍会漏绘、裁剪、越界、降低可读性或污染页面结构。
2. 按当前真实 OCR/翻译能力注入等比例缺失和拉丁字符残留后，整视口体验会受到多大影响。

交付物包括 50 个可重复视口、两类输入剖面、逐视口 JSONL、机器汇总、三张联系表、15 张代表样本和一键真机脚本。

## 3. 真实场景：用户实际如何使用

矩阵覆盖用户在普通悬浮窗中阅读外文网页的五类高频或高风险场景，每类 10 个视口：

| 场景 | 用户行为与验证重点 |
| --- | --- |
| Light 正文 | 阅读浅色技术文章；检查标题、正文、提示块和段落层级 |
| Dark 正文 | 阅读暗色文章；检查前景对比、材料重量和暗色一致性 |
| 非文字混排 | 页面含 Canvas 图表、彩色标记和分隔线；检查只改文字、不伤图形 |
| 横屏边缘 | 旋转设备后阅读双列/宽屏内容；检查右边缘、锚点和可见范围 |
| 译文长度压力 | 译文约为原文 0.5、1、1.5、2、2.5 倍；检查自动换行、字号下限和裁剪 |

每个视口生成三张图：`source` 是固定原页，`ideal` 使用准确文字框和正确译文，`current` 使用按真实遥测校准的缺陷输入。三者采用同一生产贴片渲染器和同一 `alpha=0.72` 合成方式。

这里的 `current` 是确定性影响模拟，不是第二次真实 OCR/翻译运行。校准来源为 2026-07-29 实机连续滚动：识别区域 466、失败区域 17（3.65%）、拉丁字符残留率 P90 5.71%。本轮按固定间隔注入 10 个输入框缺失和 10 个原词残留，以保证结果可复现。

## 4. 验收：逐项列出可操作标准

| 项目 | 可操作标准 | 高准确输入实测 | 判定 |
| --- | --- | --- | --- |
| 视口完整性 | 5 类 x 10，共 50 个视口全部生成 | 50/50 | PASS |
| 区域覆盖 | 所有期望文字框都有贴片，覆盖率 min/P10 = 100% | 100% / 100% | PASS |
| 裁剪与漏绘 | 裁剪区域 = 0，渲染失败区域 = 0 | 0 / 0 | PASS |
| 字号可读性 | 最小译文字号 / 原文字行高 >= 0.50 | 0.684 | PASS |
| 对比度 | 所有译文与材料对比度 >= 4.5:1 | 最低 6.41:1 | PASS |
| 非文字保护 | 保护区保持率 >= 99%，贴片与保护区交叉 = 0 | 100%，0 | PASS |
| Chrome 保护 | 系统/浏览器栏保持率 >= 99.9% | 100% | PASS |
| 变更边界 | 贴片外变更采样数 = 0 | 0 | PASS |
| 渲染性能 | 50 视口 P90 <= 160ms | P50 44ms，P90 61ms | PASS |
| A7 完整观感 | 无越界、无持续混排、材料与页面层级协调 | 结构通过；灰色矩形贴片感仍明显 | PARTIAL |

高准确输入的单次最大渲染时间为 340ms，出现在冷启动样本；稳定分位 P90 为 61ms，故性能门通过，但后续回归仍保留最大值观察。

## 5. 两类输入结果如何解释

| 输入剖面 | 整视口通过 | 覆盖 min/P10 | 裁剪 | 输入缺失 | 原词残留 | 解释 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 高准确上限 | 50/50 | 100% / 100% | 0 | 0 | 0 | 证明渲染器的确定性技术上限 |
| 当前能力校准 | 39/50 | 80% / 83.33% | 1 | 10 | 10 | 预测当前上游缺陷对整页体验的影响，不是渲染器通过率 |

当前能力校准中出现 1 个裁剪，是残留原词增加了译文长度后触发布局压力。这说明输入完整性与渲染布局并非完全独立：高准确 OCR+翻译既减少漏贴片，也减少异常长度造成的后续排版风险。

## 6. 范围：本周做什么、不做什么

本轮做：固定输入契约、50 个合成视口、Light/Dark、横屏、非文字保护、0.5-2.5 倍译文长度、普通 `alpha=0.72` 局部背景、生产渲染链路、当前能力影响模拟、机器门和人工截图复核。

本轮不做：重新评估 OCR CER/WER、翻译语义评分、真实网页黄金标注、连续滚动、触摸透传、功耗、第二品牌设备、全页主题色/高斯，以及把任何 Debug 背景模式改为生产默认。本矩阵是“渲染确定性夹具”，不替代 A5/A6 人工黄金集。

## 9. 风险：未知点及最晚升级时间

| 风险 | 当前影响 | 最晚升级时间与处理 |
| --- | --- | --- |
| 合成视口不等于真实网页 | 无法覆盖所有字体、脚本、CSS 和复杂背景 | 下一视觉候选完成后；接真实黄金视口，不以本轮替代 |

| 对比度是渲染材料与文字色的确定性检查 | 复杂底图边缘仍需截图/像素复核 | 下一轮局部羽化 A/B 前补实际合成像素门 |
| 普通模式灰色材料生硬 | A7 无法完整通过 | 下一视觉实现前冻结基线，候选必须与当前联系表并排复核 |

## 11. 后续开发引用

涉及文字框扩展、贴片合并、字号搜索、明暗前景、背景材料、窗口透明度或并行渲染的修改，必须重跑本矩阵并比较 `coverage_min`、`clipped_regions`、`minimum_text_scale`、`minimum_contrast_ratio`、保护区保持率、贴片外变化和 P90。之后再用真实黄金集验证 A5/A6；两类证据不可互相替代。

本轮依据 Apple 风格的克制材料、明暗排版、空间连续与非文字层级原则进行人工复核。该原则影响 A7 视觉判定，但没有改变机器门限。
