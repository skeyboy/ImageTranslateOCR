# 实时屏幕翻译产品场景与验收基线

> 建立日期：2026-07-28
>
> 适用范围：Android 跨应用连续屏幕翻译、悬浮控制、滚动刷新、OCR、翻译和译文贴片
>
> 同步来源：[实时屏幕识别与悬浮翻译实验账本](live-screen-translation-experiment-log.md#12-2026-07-28-产品场景与验收基线)

## 1. 结论与产品定位

产品定位为“跨应用连续屏幕翻译阅读器”。主场景是用户在外文网页、文档或第三方 App 中开启一次翻译后继续滚动阅读，而不是通用视觉搜索或系统级 Circle to Search 克隆。

本基线依据以下参考材料和当前仓库实测建立：

- YouTube 视频 `Circle to Search Just Got a Massive Upgrade – Here's Why`：描述了长按系统 Home 按钮或导航条启动 Circle to Search、圈选视觉搜索、搜索历史与隐私入口，以及跨应用屏幕翻译。
- 本地参考视频 `/Users/lee/Desktop/a390d28b47747a7c0f403dd5da8d54a0.mp4`：33.11 秒、720x1280、约 30fps；展示英文 Wikipedia 整屏切换为中文、底部控制条保持固定、页面继续滚动、停稳后整组更新译文，以及退出后恢复原文。

可以从视频确认最终交互，但不能据此判断 Google 内部使用 DOM、无障碍节点、系统 Surface、OCR Track 或多信号融合。当前项目只承诺使用公开 Android API 实现等价阅读体验，不承诺复制 Google 私有系统入口、第三方页面 DOM 重排或滚动期间的逐像素同步排版。

## 2. 目标：最终要证明或交付什么

在 Android 上交付并证明以下跨应用连续屏幕翻译闭环：

`开启悬浮翻译 -> 授权屏幕采集 -> 当前视口原位翻译 -> 页面继续滚动 -> 停稳后自动刷新 -> 原文/译文切换 -> 完整退出`

当前阶段交付物包括：

1. 可安装 APK，支持英译中和中译英。
2. 50 个真实人工标注视口及机器可读指标结果。
3. 首屏、连续滚动和退出清理三段实机录像。
4. 结构化 JSON/JSONL、失败截图和明确的 `PASS`/`FAIL` 结论。

## 3. 真实场景：用户实际如何使用

核心场景：

1. 用户浏览英文 Wikipedia、技术文档、新闻或帮助中心，开启英译中后不离开当前应用继续阅读。
2. 用户连续上下滑动长文章；运动开始时旧译文失效，页面停稳后当前视口一次性显示新译文。
3. 用户在系统设置、海外购物、酒店预订、物流或第三方 App 中临时翻译按钮、说明和商品信息，原页面仍可点击、拖动和滚动。
4. 用户需要核对时切回原文，页面滚动位置、图片和主要段落锚点不发生可见跳动。
5. 用户结束阅读后关闭翻译，译文层、录屏会话和后台识别停止。

第二优先级场景是静态 PDF、扫描页、社交帖子和图文商品页。

当前不纳入可用性声明的场景：视频字幕、直播、游戏、相机取景、快速动画页面、密码/支付/DRM 页面，以及医疗、法律等要求专业翻译准确性的内容。

## 4. 验收：逐项列出可操作标准

以下指标是后续默认配置、性能优化和发布判断的联合门。模型首次下载耗时单独记录，不计入已安装模型后的交互时延。

| 编号 | 验收项 | 可操作标准 | 证据 |
| --- | --- | --- | --- |
| A1 | 首次流程 | 入口、悬浮窗、MediaProjection 授权、语言选择和失败提示均可完成；拒绝授权后可重新发起 | 实机录像、系统状态和日志 |
| A2 | 首屏速度 | 模型已安装时，从稳定画面到完整译文提交 P50 <= 1.5s、P90 <= 2.0s | 至少 30 轮结构化时延数据 |
| A3 | 滚动稳定性 | 固定执行 30 次滚动；每次手势停稳后最多提交一次 OCR；静止 15 秒新增 OCR 为 0 | 手势脚本、`overlay_translation_completed`、`settled_viewport_restored` |
| A4 | 结果时效 | 运动开始后 150ms 内隐藏旧译文；过期 generation 提交数为 0；末次运动到提交 P90 <= 2.0s | 帧时间线和 generation 日志 |
| A5 | 覆盖完整性 | 50 个黄金视口中，源文字区域和译文贴片面积召回 P10 均 >= 90%；标题、主要按钮和正文首段关键区域召回 100% | 人工框、整屏参考、候选预览和汇总 JSON |
| A6 | 语义质量 | OCR CER <= 5%、WER <= 15%；有黄金译文时相似度 >= 0.90，或人工可接受译文区域比例 >= 90%；URL、代码、品牌和保护区不得强制翻译 | 黄金文本、译文评分和人工复核表 |
| A7 | 视觉一致性 | 译文整组原子出现，不逐行闪烁；无持续原文/译文混排；图片、图标和非文字区域无大面积污染；亮色、暗色均可读 | 合成预览、像素门和实机录像 |
| A8 | 触摸透传 | 控制条之外连续执行 30 次点击、拖动和惯性滚动，底层页面成功响应率 100% | UIAutomator/ADB 手势和录像 |
| A9 | 原文切换 | 原文/译文切换前后滚动位置偏移 <= 16px，图片和主要段落锚点不跳动 | 切换前后截图配准 |
| A10 | 退出清理 | “取消预览”后 500ms 内清除译文；“结束”后释放译文 Window、控制 Window 和 MediaProjection，随后静止 15 秒新增 OCR 为 0 | Window/服务状态、日志和录像 |
| A11 | 隐私与权限 | 屏幕采集必须由用户显式授权并有前台通知；屏幕内容不上传、不作为长期文件保存；网络仅用于明确的模型下载；安全页面失败时不得绕过系统限制 | 权限流程、网络检查和数据留存检查 |

黄金视口最低矩阵：

| 场景 | 最少视口数 |
| --- | ---: |
| 竖屏亮色英译中 | 10 |
| 竖屏暗色英译中 | 10 |
| 横屏正文 | 10 |
| 中译英 | 10 |
| 代码、品牌和 UI 混排 | 10 |

任何单类缺失都不能以总样本数抵消。

背景效果使用同一批黄金视口做配对人工对比，顺序为“关闭、主题色、高斯模糊”，记录可读性、页面一致性、原文残留、非文字污染和渲染时延。首次默认必须为关闭；主题色和高斯模糊在 A7 与性能门通过前只能由用户手动选择，不能自动开启。

## 5. 范围：本周做什么、不做什么

本周范围：

- Android 英译中、中译英。
- 网页和文档型页面的竖屏、横屏、亮色、暗色验证。
- 首屏识别、滚动刷新、原文切换、触摸透传和退出清理。
- 扩充真实黄金集，建立覆盖、语义、P90、交互和资源释放联合门。
- 正确性不足时自动回退整屏识别。

本周不做：

- Circle to Search 的圈选搜索、物体识别和搜索历史。
- 多语言扩展、iOS/macOS 对齐和云端大模型翻译。
- 修改第三方应用 DOM 或让译文在滚动期间持续跟随原文移动。
- 以降低覆盖率或语义门限换取差分命中率和速度。
- 视频、直播、游戏和相机画面的逐帧翻译。

停止条件：

1. 截至 2026-07-30 18:00，若源文字区域或译文贴片面积召回 P10 仍低于 90%，停止继续扩大差分命中范围，默认固定使用严格整屏回退。
2. 若覆盖和语义达标但 P90 超过 2 秒，记录为性能遗留，不得通过放宽质量门解决。
3. 若出现过期结果覆盖新视口、触摸被全屏译文层拦截或结束后仍在采集，视为阻断问题，停止性能实验并优先修复生命周期和交互正确性。

## 8. 风险：未知点及最晚升级时间

| 风险或未知点 | 影响 | 最晚升级时间与处理 |
| --- | --- | --- |
| Google 参考效果可能依赖私有系统能力 | 无法逐项复制入口、页面语义和滚动同步 | 2026-07-28 锁定“公开 API 下视觉等价”的产品边界 |
| Track 差分实测面积召回 P10 曾为 82.11% | 未达到 90% 产品门，可能漏译 | 2026-07-30 18:00；不达标即保持严格整屏回退 |
| GMS OCR 模型在国内或非认证设备下载失败 | 首次使用不可用或语言能力不完整 | 2026-07-29 决定 bundled 变体和无网降级提示 |
| 小字、代码、品牌和中英混排误识别 | CER/WER、翻译和保护区失败 | 2026-07-30 完成专项黄金集；未通过则从可用性声明排除 |
| 不同厂商限制后台、悬浮窗和录屏 | 单机结果不能代表广泛兼容 | 2026-07-30 前完成第二品牌验证；否则只声明已测设备范围 |
| 延迟、覆盖率和功耗相互冲突 | 可能以速度优化引入漏译或耗电 | 始终按“正确性 > 完整性 > 延迟 > 功耗”决策，不单独以差分命中率判定成功 |
| 屏幕可能包含敏感信息 | 隐私和合规风险 | 发布前完成数据留存与网络检查；安全页面必须遵守系统阻止结果 |

## 9. 后续开发引用规则

1. 每轮实时屏幕翻译开发必须在实验记录中引用本文。
2. A1-A11 必须逐项填写实测值以及 `PASS`、`FAIL` 或 `N/A`；使用 `N/A` 时必须说明该修改为何不影响对应指标。
3. 只有 A1-A11 全部通过，或对明确不受影响的项目给出可审计 `N/A`，实验结论才能标记为“保留并进入默认配置”。
4. 性能收益只有在覆盖、语义、交互、隐私和资源释放门同时通过后才成立。
5. 本文与实验账本第 12 节是同一基线；修改指标、范围或停止条件时必须同步更新两处，并在实验记录中说明变更原因。
